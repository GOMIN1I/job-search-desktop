# Сервер поиска

Сервер выполняет поиск по расписанию, когда компьютер человека выключен или спит. Он использует тот же код, что приложение: источники, правила, «дополнительные инструкции для ИИ» и расписание в часовом поясе человека. Приложение отправляет на сервер профили поиска, выбранные источники и расписание, а при следующем запуске забирает найденное, само оценивает его и показывает уведомления.

## Что хранит сервер

- профили поиска (направления, условия, инструкции), выбранные источники и исключения, расписание;
- найденные объявления за последние 30 дней — до того, как их заберёт приложение;
- доступы к hh.ru и Adzuna — только если человек это разрешил; хранятся зашифрованными ключом `SERVER_SECRET`.

Аккаунт анонимный: приложение получает случайный токен. Кнопка «Отключить и удалить данные с сервера» удаляет всё.

## Запуск

Нужен Node.js 22+ или Docker и постоянный диск для данных.

```bash
npm ci
npm run build
DATA_DIR=/var/lib/jsd SERVER_SECRET="$(openssl rand -hex 32)" PORT=8787 node server/dist/server.js
```

Docker (из корня репозитория):

```bash
docker build -f server/Dockerfile -t jsd-search-server .
docker run -d -p 8787:8787 -v jsd-data:/data -e SERVER_SECRET="$(openssl rand -hex 32)" jsd-search-server
```

Готовые настройки для хостингов: [`render.yaml`](render.yaml) (Render, Blueprint с диском) и [`fly.toml`](fly.toml) (Fly.io, с томом `/data`). Сервер должен быть доступен по `https://` — приложение не подключается к удалённому серверу без шифрования.

| Переменная | Значение |
|---|---|
| `SERVER_SECRET` | обязательна, не короче 32 символов; ключ шифрования доступов. Не меняйте после запуска |
| `DATA_DIR` | папка данных (по умолчанию `./data`) |
| `PORT` | порт (по умолчанию 8787) |
| `MAX_ACCOUNTS` | ограничение числа аккаунтов (по желанию) |

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | проверка работы |
| `POST` | `/v1/accounts` | новый аккаунт → `{ id, token }` |
| `PUT` | `/v1/sync` | профили, источники, исключения, расписание, (по согласию) доступы |
| `GET` | `/v1/results?after=<cursor>` | собранные объявления после курсора |
| `GET` | `/v1/status` | расписание, следующий запуск, последние поиски |
| `POST` | `/v1/run-now` | поиск сейчас |
| `DELETE` | `/v1/accounts` | удалить аккаунт и все данные |

Все пути, кроме `/health` и `POST /v1/accounts`, требуют `Authorization: Bearer <token>`.

Сервер соблюдает те же лимиты источников, что и приложение (минимальный интервал опроса, пауза между страницами). Если пользователей много, учитывайте, что все запросы к источникам идут с одного адреса сервера.
